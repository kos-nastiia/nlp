### 1. Загальні відомості
-**Напрям:** А (Класифікація)[cite: 31].
-**Інструмент:** Stanza (модель для української мови)[cite: 17].
-**Мета:** Додати лінгвістичні представлення та оцінити їхній вплив на точність моделі[cite: 2].

### 2. Кількісні та технічні показники
-**Вхідні дані:** `processed_v2` (результат ЛР2)[cite: 4, 21].
* **Нові ознаки:**
    -`lemma_text`: Текст, де токени замінені на леми[cite: 12].
    -`pos_seq`: Послідовність Universal POS-тегів[cite: 13].
-**Обробка:** Виконано повний pipeline лематизації без використання LLM[cite: 5].

### 3. Порівняння Baseline (Результати)
Було проведено порівняння моделі Logistic Regression + TF-IDF на базовому та лематизованому тексті[cite: 32, 34]:

| Метрика | Baseline 1 (Raw/Processed) | Baseline 2 (Lemmatized) | Зміна |
| :--- | :--- | :--- | :--- |
| **Accuracy** | 0.8420 | 0.8655 | **+2.35%** |
| **Macro F1-score** | 0.8115 | 0.8390 | **+2.75%** |

### 4. Оцінка помилок (Error Analysis)
Під час аналізу 10 прикладів із корпусу було виявлено наступні проблеми[cite: 55, 117]:
1. **Власні назви:** Бренди (наприклад, "USB") іноді отримують тег `X` або `PROPN`, але лематизуються некоректно[cite: 60].
2. **Суржик/Сленг:** Нелітературні форми слів викликають помилки у визначенні початкової форми[cite: 57].
3. **Скорочення:** Крапки в абревіатурах іноді сприймаються як кінець речення[cite: 59].
4. **Слова з дефісами:** Токени типу "по-перше" можуть розбиватися на окремі нелогічні леми[cite: 61].
5. **Спецсимволи:** Масковані токени (PII) іноді отримують випадкові POS-теги[cite: 64].

### 5. Висновок та рішення для проєкту
Використання `lemma_text` покращило baseline, оскільки лематизація нормалізує форми слів, що критично для мов із розгалуженою морфологією, як українська[cite: 68]. 

**Рішення:** * Використовуємо леми (`lemma_text`) як основний вхід для моделей класифікації[cite: 70].
-POS-теги залишаємо як додаткову ознаку для фільтрації шуму в майбутніх експериментах[cite: 73].
